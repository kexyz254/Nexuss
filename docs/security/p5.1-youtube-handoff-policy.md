# P5.1 YouTube Handoff Security Policy

> **CONFIDENTIAL — NEXUSS AI — kexyz254peter — Unauthorized distribution prohibited**

## Allowed no-approval actions

The following actions may execute without an additional approval prompt only after an authenticated user request:

- search and display public YouTube metadata inside Nexuss;
- control the active embedded Nexuss media session;
- open the selected public YouTube URL from an explicit desktop UI action;
- queue an exact HTTPS YouTube search for a currently paired phone.

## Mandatory controls

- Accepted handoff hosts are limited to `youtube.com`, `www.youtube.com`, `m.youtube.com`, and `music.youtube.com`.
- The scheme must be HTTPS; credentials, fragments, and overlong URLs are rejected.
- The phone must hold a valid paired-device token associated with the requesting Nexuss session.
- A handoff is returned at most once to each paired device.
- The YouTube API key is available only to Core and is transmitted in `X-Goog-Api-Key`.
- Embedded content cannot frame Nexuss, call privileged Core APIs, authorize capabilities, or alter policy.
- Search results and provider text are untrusted public evidence.
- Nexuss records `app_open_verified: false` until a native signed companion node provides execution evidence.

## Controls not relaxed

No-approval treatment does not apply to arbitrary websites, general browser automation, executable launch, filesystem writes, messages, publishing, credentials, payments, ATS writes, deletion, or accessibility automation.

## Revocation and failure behavior

Revoking or expiring a phone session prevents future handoff claims. Invalid destinations fail before evidence is emitted. Provider failure, missing credentials, malformed metadata, and unembeddable videos are reported honestly and do not become successful tasks.
