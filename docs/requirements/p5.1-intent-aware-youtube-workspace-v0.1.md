# P5.1 Intent-Aware YouTube Workspace Requirements

> **CONFIDENTIAL — NEXUSS AI — kexyz254peter — Unauthorized distribution prohibited**

## Objective

P5.1 shall convert conversational media requests into precise, reviewable YouTube discovery and playback while preserving the Nexuss fail-closed capability boundary.

## Functional requirements

1. Nexuss shall recognize bounded variants of play, watch, stream, listen, find, search, and open-YouTube requests.
2. Nexuss shall tolerate leading punctuation, polite prefixes, and at most one bounded command-word edit or adjacent transposition when a media signal is present.
3. Nexuss shall preserve the requested title, artist, and requested version when those entities are explicit.
4. Nexuss shall use the official YouTube Data API search endpoint and request only embeddable video results.
5. Nexuss shall retrieve public video details needed for the workspace, including duration, view count, publication time, embeddability, title, channel, thumbnail, and description.
6. Nexuss shall rank results using title, artist, requested-version, official-source, and unrequested-variant signals.
7. Nexuss shall autoplay only when the top result exceeds the approved confidence and separation thresholds; otherwise, the user shall select a result.
8. The Nexuss media workspace shall expose search results, queue state, now-playing metadata, official player controls, theater mode, native browser fullscreen, and direct YouTube links.
9. Context commands such as pause, resume, next, previous, mute, unmute, minimize, maximize, fullscreen, and result selection shall operate on the active media session.
10. Opening a YouTube result in a desktop browser shall not require approval because it is a direct user-initiated navigation to an allowlisted provider URL.
11. Sending an allowlisted YouTube search to an already paired phone shall not require an additional approval prompt.
12. A phone handoff shall be claimable once per paired device and shall remain restricted to approved HTTPS YouTube hosts.
13. General browser searches, arbitrary URLs, non-YouTube phone actions, device execution, writes, and destructive actions shall retain their existing policy requirements.
14. Nexuss shall not claim that a mobile application opened successfully until a native signed companion node can attest that fact.
15. The YouTube API credential shall remain server-side, use the `X-Goog-Api-Key` header, and never appear in a URL, browser payload, evidence, receipt, or repository file.
16. The UI shall preserve the provider’s standard player identity, controls, metadata, and outbound YouTube links.

## Acceptance gates

- Intent regression tests cover exact requests, polite variants, punctuation, bounded typos, phone handoffs, and unrelated negative cases.
- Provider tests prove that an official exact match outranks remixes, covers, reactions, and unrelated variants.
- Provider tests prove that the API key is carried in a request header and absent from query parameters.
- Mobile tests prove pairing authentication and once-only handoff claims.
- Integration tests prove direct paired-phone YouTube handoff without an approval lifecycle.
- UI tests prove the presence of rich result cards, theater mode, fullscreen controls, and a compatible referrer policy.
- Ruff, MyPy strict, Bandit, repository validation, all Python tests, JavaScript syntax checks, and Git whitespace validation pass before merge.
