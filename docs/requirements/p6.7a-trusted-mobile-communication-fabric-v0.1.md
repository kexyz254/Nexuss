# P6.7A — Trusted Mobile Communication Fabric v0.1

## Problem

A user’s operational information is fragmented across the phone dialer, SMS,
WhatsApp, Instagram, Facebook Lite and content manually shared from other
applications. Nexuss needs a lawful, auditable mobile signal plane without
pretending that a paired device grants unrestricted access to private
application data.

## Goals

- Accept allowlisted communication notifications from a paired Android device.
- Accept content the user explicitly shares to Nexuss.
- Normalize phone, SMS, WhatsApp, Instagram and Facebook Lite signals.
- Suppress OTPs, passwords, tokens and credential-shaped notification content.
- Provide a bounded read-only feed and attention summary.
- Prepare exact mobile actions on the desktop.
- Bind every action to one paired device, exact payload hash and short expiry.
- Require biometric or device-credential approval on the target handset.
- Execute only allowlisted platform actions and return scoped evidence.

## Supported action types

- `dial_handoff`: open the system dialer; never place a call automatically.
- `sms_compose`: open the SMS composer; never background-send SMS.
- `notification_reply`: use an app-provided Android RemoteInput action.
- `open_conversation`: invoke an app-provided notification PendingIntent.

## Explicit non-goals

- Reading private WhatsApp, Instagram or Facebook databases.
- Recovering deleted messages.
- Call audio recording.
- Credential, cookie or OTP collection.
- Accessibility-driven screen scraping or autonomous UI control.
- Claiming delivery when only an Android handoff or PendingIntent dispatch was verified.

## Trust statement

A paired device is an authenticated endpoint, not unlimited authority. Read
access depends on permissions the user grants in Android Settings. Every
external action requires an exact action proposal from the local Nexuss control
plane and a matching on-device approval.
